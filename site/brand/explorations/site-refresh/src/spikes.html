How do you know your agent built what you meant?

  • Because you wrote it down: a design, in plain English.
  • Because everything the agent builds comes from that design.
  • Because you can check: one ID grep returns the requirement, its tests, and its code.
  • Because LID helped you get there.

Code that runs can still miss what you meant. With LID (Linked-Intent Development), the design stays linked to everything built from it. Fix it once, the agent cascades the change, and you sign off or push back at every step.

A short request leaves the decisions to your agent.

Suppose you ask your agent to add a feature to your app:

You, to your agent

Give new users a 30-day free trial.

It sounds complete, but it leaves these decisions to the agent:

  • When the trial startsAt signup, or the first time they use the app.
  • What happens when it endsThe account locks, or the card on file is charged.
  • Second trialsWhether someone can start another with a new email address.
  • When exactly day 30 endsEasy to miss, and someone will notice.

Someone who signs up at 11 p.m. on the 1st, in Tokyo, will notice how the last one was decided.

Each level you write down rules out what you didn't mean.

Each level of design is a constraint on what the agent can build. In the drawing, each one is a ring around the programs it still allows. Scroll through the free trial, one level at a time.

  1. Start with the request

    You, to your agent

    Give new users a 30-day free trial.

    Your agent could build that in many ways. The trial could start at signup or at first use, end at the server's midnight or exactly 720 hours later, and lock the account or charge the card. Picture each possible program as a dot in a field like this one. A request this short leaves the whole field open, and the agent picks one dot.

  2. Write down why

    This is a high-level design, or HLD: why the project exists and what it must get right. It lives in your repository, like every LID document. Its ring is the first constraint, and it rules out programs that miss the point of the trial.

  3. Write down which way to lean

    This is a tenet: your project's tie-breaker between two good options, kept in your HLD. Another business could reasonably pick the other side. This one rules out a whole region before anyone thinks to ask, including ending trials at the server's midnight, which would cut a Tokyo signup's trial 14 hours short.

  4. Write down how

    This is a low-level design, or LLD: how one part works. Its smaller ring sits inside the HLD's, clear of what the tenet ruled out.

  5. Write down the rules

    These are requirements: one line each, with an ID, in a pattern called EARS. Each one draws a smaller ring, and the program has to sit inside all of them. A few programs still fit.

  6. Test first, then code

    ✗fails, before the code exists ✓passes, once the code lands

    The test aims at the one program you meant. The code carries the same @spec TRIAL-003 comment, so the ID leads to everything built from that line.

Change your mind in one place, and the agent carries it down.

That may feel like a lot to write down for one free trial. It pays off when you change your mind. You change the highest level the change touches, and the agent follows the links from there to everything that has to change, while you review each level.

  1. Say what should change

    You, to your agent

    End trials at midnight in each user's own time zone.

    This changes how the trial ends. The low-level design no longer says what you mean, so the agent re-checks the decisions built on it and adjusts them.

  2. Check what still holds

    First the agent checks the change against the levels above it. New users still get 30 days free, and the tenet still favors the customer. The HLD and its tenet hold, and they mark out where the new design can go.

  3. Find the new design

    Your request leaves one question open: which midnight? The agent drafts two answers for trial-design.md.

    1✗Draft 1The trial ends at midnight on day 30, in the user's time zone.
    2✓Draft 2The trial ends at the first midnight, in the user's time zone, after 720 hours.

    Draft 1 would cut a late-night signup's trial by most of a day, so the tenet rules it out. Draft 2 gives everyone at least 30 full days, and you approve it at the pause.

  4. Follow the ID down

    ✗ends a Tokyo trial at the first local midnight after 720 hours: fails ✓the same test, after the code changes: passes

    The agent searches for TRIAL-003 and finds the test and the code that cite it. TRIAL-001 and TRIAL-002 still hold, so their rings stay put. TRIAL-003 changes, its test changes and fails, then the code changes and the test passes.
