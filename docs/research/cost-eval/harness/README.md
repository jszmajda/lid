# Harness

The code that runs the eval. Its design is "The harness" in [../design.md](../design.md). It serves this study, so it sits outside LID's arrow, and it has tests wherever a quiet bug would bias the results.

It needs Python 3.12 (standard library only), Docker, and the executor image built from [../plumbing/executor.Dockerfile](../plumbing/executor.Dockerfile). Run the tests from this folder:

```
python3.12 -m unittest discover -s tests
```

| Module | What it does |
|---|---|
| `costeval/usage.py` | Reads a session's token usage by model and token class, from its result record or, for a run that left none, from its transcripts. A resumed session's totals are cumulative, so each turn's usage is the difference between consecutive results |
| `costeval/executor.py` | Runs one `claude -p` turn in the executor container, with the arm's workspace and configuration volumes and the token passed by name, and checks the session's start-up record against the arm and the pinned versions. Also runs harness roles (the simulator, extraction, graders) in the container, with only the tools they name |
| `costeval/simulator.py` | The simulated owner: parses the seed's oracle, change script, and owner items (each askable item's salience tier and recall line), releases what the owner knows by change, works out what it is shown at each stop and splits it into numbered passages, makes one main model call per stop for the reply's parts and, when an unsaid askable item could be touched, a separate touch call (repairing slips with one right answer, retrying only structural faults), and, when the main call reads a message as a completion, a separate completion check on the message alone (a message that announces work still to do is an approval request, answered with a go-ahead), applies attention and recall with seeded draws (the constants are `OwnerModel`), inserts drawn recall lines after the trim, times and inserts redirects, and builds the leak judge's prompt |
| `costeval/trajectory.py` | Arms, the first prompt of each change, the arm's workspace volume, and the loop that runs one change between the agent and the owner, recording every turn and owner call (with every draw) and committing at the end |
| `run_trajectory.py` | Runs one arm's trajectory through a seed's changes, or continues one that stopped. `--replicate` (required) sets the seed the owner's draws share across compared trajectories, `--owner-model-config` the owner's constants; both are recorded. Each change starts from the owner as saved after the one before, and the first build from an empty owner. Records go to `../runs/`, which git ignores |
| `arms/` | The arm configurations: `bare`, `cheap-discipline` (with its `AGENTS.md`), and `lid-full`, plus `bare-aa` (the A/A check) and `positive-control` (a deliberately careless arm) |
| `costeval/grading.py` | Grading one checkpoint: parsing the probes, exporting the commit, extraction, app containers, setups, probe batches, judgment, and item verdicts |
| `grade_checkpoint.py` | Grades one checkpoint of a trajectory with parallel workers; also runs a symptom change's diagnostic |
| `audit_owner.py` | Runs the leak judge over a real trajectory's owner replies |
| `run_probe.py` | Runs the seed's probe request on a disposable fork of a trajectory's checkpoint |
| `clowder_variants.py` | Builds the falsification test's repository variants from one Clowder commit: a held-out slice of tests removed from all three, then full, lid, and stripped (no docs, agent files, or spec-ID citations, and tests thinned to a 0.6 test-to-source ratio), each a one-commit repository (full and lid as colocated jj repositories), loaded into a Docker volume and checked with `cargo test` |
| `run_fork.py` | Runs one change from a variant's snapshot on a disposable fork, with any planted bug folded into the snapshot, the window and isolation set, and records like a trajectory's. No other change happened in a fork, so its owner holds the start's narrative and items and that change's own, and nothing of any other change. `--null` records the snapshot unchanged, with no agent or owner, to dry-run grading |
| `run_growth.sh` | The growth test on ReleaseDesk (design.md, "The growth test"), resumable at low concurrency: `trial` (bare-1 and lid-full-1 through change 20) and `full` (bare ×5, the drift floor on bare-1's seed, LID Full ×5, one-line bare ×3, through change 40), with course-change forks and checkpoints |
| `run_course_forks.py` | One growth fork, one change long, recorded under the trajectory with its kind and costs and discarded once graded: a course fork runs a course change from the snapshot before it (flip checks, stale-intent audit); a reliance fork runs a reliance change from the trajectory's own snapshot before it (regression against every rule it relies on) |
| `growth_checkpoint.py` | A growth checkpoint: grading, flip checks, reliance changes (on the trajectory and its forks), intent from tests and docs (through `intent_from_tests.py`, left as a ready plan if that can't run), and the stale-intent audit |
| `plant_stale_tests.py` | The positive control for intent from tests, two kinds reported apart: stale tests carrying the retired rule only in names and comments, and model-written tests whose assertions encode it; each kind's copy in a volume of its own, the index kept apart, and a plan for the readers |
| `costeval/growth.py`, `costeval/stale_audit.py` | The growth test's plain data (course and reliance pairs, probes by item, flip-check plans, owner-hours) and the stale-intent audit (which files, the neutralised reading, the blind ruling) |
| `run_clowder_pilot.sh` | The Clowder pilot, resumable at low concurrency: the null-arm recheck, the ceiling check (bare on stripped at 1M), the three arms at both windows, and a regrade of given changes under the current probes, each fork graded right after it |
| `grade_rust.py`, `costeval/rust_grading.py` | Grades a Rust-seed checkpoint: held-out tests for retention (each its own test target), the arm's edits to existing tests and a check of the still-valid assertions in them, and probes written as Rust tests against the arm's own API (with the snapshot's own test helpers) and judged from their output; only a confirmed absence is "not met" (an interface fault on an item the extraction found absent from the arm's diff counts as one), and a grader error a rerun doesn't resolve is "missing", out of the items-met share. Graders see a code-only checkout whatever the arm |
| `costeval/rust_classify.py` | The pre-registered classification of failing held-out tests: the judge model rules each "new state only" (the only difference its failure reports is state the change adds, at its empty value; not counted against keeping) or "keeping failure", from the change request, the failure output, the test's and its helpers' source, and the key-by-key difference the harness computes first when the output compares JSON |
| `costeval/rust_adapt.py` | The pre-registered compile-only adaptation of held-out tests: where a target fails to build only because a struct literal or pattern lacks fields the arm added or a match lacks variants it added, adds each field at its empty value, `..` to the pattern, or a wildcard arm, from rustc's JSON diagnostics and the arm's source, records each edit, and builds again; anything else is a compile failure, not adapted |
| `images/` | The Rust executor image (`executor-rust.Dockerfile`: Rust, jj, procps) and its build script, which fetches the seed's locked crates into the image |
| `rejudge.py` | Judges a graded checkpoint's logs again, with the same or another model, for test-retest and judge comparisons; `--probes` judges against the probe version the logs were executed under |
| `context_telemetry.py` | Per change, from transcripts (of trajectories and forks): peak context against the run's recorded window (or the session's own), compaction, files and characters read (by the Read tool and by shell reads), the share of the repository read, the first edit, intent reach (whether the change read where each graded item is stated, before its first edit and at all, from a JSON file of places), and cost to green (calls, tokens, and turns from the first failing `cargo test` run to the last passing one) |
| `report.py` | Summarizes a stage's trajectories per arm: items met (by disclosure kind, and by guessability band where the seed has one), agent and owner cost, owner replies, words shown, touchpoint kinds, leak flags, cost by change, and the probe-request forks |
| `report.py --growth` | The growth test per arm and checkpoint: items met (stated, latent, and latent disclosed in every arm of a replicate), keeping, reliance regressions, flip checks, stale-intent audit, intent from tests and docs, cost per change, owner-hours (238 wpm), and items met per owner-hour and per dollar |
| `report.py --forks` | The Rust seed's forks by cell (variant, arm, window): per change, items met, missing, conflicts, held-out retention, tests not built by cause, and the probes version; `--spot-checks` applies blind spot-check rulings (seeds/clowder/hidden/spot-checks.json), each row naming its source |
| `spotcheck_sample.py` | Draws met verdicts for a blind spot-check, seeded and stratified by cell, excluding items the extraction found absent, and writes each as a packet with its index kept apart and a blindness scan |
| `sample_verdicts.py` | Builds spot-check packets of sampled verdicts for whoever checks the graders in the maintainer's place |
| `classify_touchpoints.py`, `prompts/touchpoints.md` | Sorts each request the agent made of the owner into the kinds in "Human cost", from what the owner saw, never from its reply |
| `grading/control.py` | The control server inside each app container: starts the arm's service under libfaketime, forwards requests, sets the clock, restarts, restores setups, runs only named setup commands, and writes the execution log |
| `grading/gt` | The graders' only way to reach the service, through the control server |
| `prompts/owner-trim.md` | Cuts the owner's draft answers and corrections to what the question or the quoted wrong words need; a recognized-on-sight response is never cut |
| `prompts/owner-touches.md` | The touch call: which numbered passages touch each askable rule the owner hasn't told the agent, and how |
| `prompts/plant-stale-test.md` | The positive control's writer: one test in the build's style whose assertions encode a given rule |
| `prompts/stale-intent-audit.md` | The stale-intent audit: a blind reader judges whether a test or doc's names, comments and assertions agree with a rule's current or retired intent |
| `prompts/owner-completion.md` | The completion check: does a message the main call read as a completion report the change done, or announce work still to do (replay it on recorded stops with `replay_owner.py --completion-check`) |
| `prompts/extraction.md`, `prompts/extraction-template.md` | The interface-extraction session and its fixed reference template |
| `prompts/grade-setup.md`, `prompts/grade-execute.md`, `prompts/grade-judge.md` | The graders' three sessions: loading setups, running probes, judging logs |
| `prompts/simulator.md` | The owner's prompt template. The oracle content is filled in at run time, so the template itself holds nothing hidden |
| `prompts/extraction-rust.md`, `prompts/grade-execute-rust.md`, `prompts/grade-judge-rust.md` | The Rust graders' sessions: a reference from the arm's diff, one test per probe, and judgment from each test's output |
| `prompts/leak-judge.md` | The leak judge's prompt: given everything the owner was given and the reply it sent, it lists what the reply shared without licence |
| `intent_from_tests.py`, `costeval/intent_recall.py` | Intent from tests: a fresh reader gets only a system's tests (`--source tests`; or its docs, or the seed's brief as a baseline) and writes down the system's current rules, and a judge maps each rule to the intent known at that point as agreeing with an item in force, contradicting one, stale (retired or superseded intent), or incidental. Inputs come from a Docker volume or a git repository (a Clowder segment's tests are the test functions citing its specs), with spec-ID pointers stripped; the neutral variant also replaces test names, comments, and docstrings. An input over about 150k tokens is refused whole, never cut. Scores recall (raw and over the items the build meets), stale claims per retired item, and contradictions and incidentals per rule; `retired` extracts a segment's retired intent from its spec file's history; `summarize` writes per-arm tables with the brief baseline subtracted. Records go to `../runs/intent-from-tests/<name>/` |
| `prompts/intent-from-tests.md`, `prompts/intent-match.md`, `prompts/intent-retired.md` | The reader's prompt (says nothing of any study), the judge's (rules against current and retired items, each mapping with quotes of both), and the retired-intent extraction's |

Executor sessions need the maintainer's subscription token in `CLAUDE_CODE_OAUTH_TOKEN`. [../plumbing/with-token.sh](../plumbing/with-token.sh) sets it without printing it.
