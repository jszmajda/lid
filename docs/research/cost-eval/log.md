## 2026-11-23: M2f's results, openGym mapped, and M2h prepared

**M2f ran** (bare on the stripped repository against LID Full; 12 changes × 3 forks; Sonnet 5.5 at the 1M window; a renaming dose on three changes; a repair fork for every miss). Before any run the grading was checked both ways, and both checks caught flaws first: keep-as-before rows voided as conflicts (now guard rows), rows met through untouched code voided (now an "inherited" extraction status), one wrong right build, and one incomplete retired-test list. In the end the untouched snapshot met no new row, and a right build of every change met every row.

Every kept dependency came with the change fully implemented. The tie hides different misses. On change 20, LID kept the dependency in 3 of 3 forks and bare in 0 of 3; repairs fixed bare's misses there in none of three. LID's docs say the shell reads the retained report, and two bare forks never opened the file that does. On changes 16 to 18, bare kept 7 of 9 and LID 4 of 9. Four of LID's five misses searched the design docs and the crate being edited, then stopped at the segment boundary ("I touched only the colonies segment"). The shell's specs restate the rules, but nothing on the core side points at them. A fifth found the shell's counts in its edge audit, asked, and was told "no preference" by an owner who doesn't know the code. Bare agents grep the whole tree, where the shell's literal strings come up first.

LID's arm ran under Clowder's own instruction file, which tells agents to resolve phase reviews below the HLD against the tenets rather than ask the owner; it still stopped 60 times across 36 forks. Renaming shared concepts made no clear difference. Change 15's first probes read one accessor while seven of twelve builds added another. A second version, testing what the owner sees, regraded its main and dose forks from each fork's saved diff, on trees checked byte for byte against what was first graded; the numbers above use it. A blind spot check upheld 12 of 12 verdicts against the final grading. Three forks per cell is grade C evidence at best, and the setup favours LID: full docs against a stripped copy with thinned tests.

**openGym mapped.** LID's arm on openGym starts from `/map-codebase`, run as an executor session that answers the owner's questions itself. Four draws took 10 to 21 minutes and 59M to 153M tokens each, and produced 815 to 1,195 specs; each LID replicate gets its own draw. Each recorded rules inside components but rarely the ties between them, and each departed from the skill: it chose a segmentation without reading its own survey, accepted sampled reading, and invented a cap on specs per file. Claude Fable judged the maps fair samples of what the skill delivers at this model and effort. The skill's faults are filed as LID issues #133 and #134.

**M2h prepared.** Twelve changes, eight crossing components and four controls, were drafted by GPT-6.2 Sol and reviewed by Claude Fable and GPT-6.2 Astra. Each is tiered by how findable its dependency is: one hidden, five a grep away, two documented. Each fork is scored on two counts, whether it built the requested rule and whether it kept, broke or never exercised the dependent behaviour, so an arm that builds nothing gets no credit for agreement. Every dependency probe reads not exercised on the pinned tree, broken on a one-sided build and kept on a right build, and every mutant fails its target. The harness was built in a separate workspace while M2f ran, then merged. The Docker VM was resized to 6 CPUs and 10 GB.

## 2026-11-22: A brownfield subject the model hasn't seen, and M2f's null check

**Contamination.** Before building a brownfield seed, a probe checked whether the executor, Claude Sonnet 5.5 with no tools, already knows each candidate codebase. It was asked to name one side of a dependency given the other, to continue file starts, and to recall internals with nothing shown. Paperless-ngx is memorised: 81% on dependency recall and 82% on pure recall, with exact constants. Clowder scored 14% and 22%, and its history starts after the model's training cutoff. A test of whether agents find hidden dependencies would measure memory on Paperless-ngx, so it was dropped (decisions.md).

**A post-cutoff subject.** A scout searched GitHub for multi-component projects created after July 2026. Its top pick is openGym, a fitness app with a Node API, a React web app, native shells and an MCP server: about 155k source lines, created 2026-07-18, pinned at e4a68a9. The full probe puts it level with Clowder: 18% on dependency recall, 21% on pure recall (10% on arbitrary values), against 78% for the Paperless-ngx control in the same batch. Mining found 5 cross-component dependencies that are genuine under the strictest reading and 10 under the reading used for Clowder. On each verified one, a one-sided wrong build fails a probe while every existing test passes. Three are found by neither a name search nor a value search. The API half is small, about 22k lines, and the project cross-references heavily, so several dependencies are one hop from the edited file. The details stay in the hidden seed until the runs finish.

**M2f's null check.** Graded on the untouched Clowder snapshot, M2f met no new-behaviour row, and every dependency probe and held-out test passed. Five keep-as-before rows (shy colonies nap at the same rate as before, and the like) were met, as they should be, but the grader voided them: it treats a met verdict as a conflict when extraction finds no code addressing the rule, and code that rightly stays the same has none. Those rows are now guard rows, exempt from that rule and reported apart from new behaviour. A right-build phase grades each change's correct build through the same pipeline, as the probes' positive control; right builds for the four control changes are being added.
