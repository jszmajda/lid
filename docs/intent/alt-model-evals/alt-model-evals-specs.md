## Invocation

- `[x]` **ALT-EVAL-CLI-001**: In its single-batch form, the runner SHALL accept three positional arguments, in order: a skill directory name, an eval-ID selector, and an OpenRouter model ID.
- `[x]` **ALT-EVAL-CLI-002**: The runner SHALL resolve the skill name to exactly one `plugins/*/skills/<name>/` directory holding an `evals/evals.json`; when the name matches zero or more than one such directory, the runner SHALL exit non-zero before staging anything and name the matches (or their absence).
- `[x]` **ALT-EVAL-CLI-003**: The runner SHALL accept an eval-ID selector that is either the word `all` or a comma-separated list whose items are each a single integer ID or an inclusive range written `A-B`, matched against each eval's `id` field.
- `[x]` **ALT-EVAL-CLI-004**: When an integer named as a single item in the selector does not exist in the suite, or a range item matches no existing ID, the runner SHALL exit non-zero before running any eval and name the offending items; a range item selects the existing IDs within its bounds, and gaps inside it are not errors.
- `[x]` **ALT-EVAL-CLI-005**: In the single-batch form, the runner SHALL accept `--runs N` (a positive integer, default 1) and run each selected eval N times, completing all runs of one eval before starting the next, with evals taken in ascending ID order.
- `[x]` **ALT-EVAL-CLI-006**: The runner SHALL accept `--timeout SECONDS` (a positive integer, default 1800) as each turn's run limit: the longest the harness may run, measured from the moment the harness process starts.
- `[x]` **ALT-EVAL-CLI-011**: Where `--variant NAME` is given, the runner SHALL pass NAME unchanged to the harness's `--variant` option for every run in the batch; where it is omitted, the runner SHALL pass no variant.
- `[x]` **ALT-EVAL-CLI-012**: The runner SHALL accept `--effort LEVEL` (default `medium`) and, unless LEVEL is `default`, SHALL write it into the run's `opencode.json` as the `reasoning.effort` option of the model under test, for every run in the batch; with `--effort default` it SHALL write no effort option.
- `[x]` **ALT-EVAL-CLI-013**: The runner SHALL accept `--idle-timeout SECONDS` (a positive integer, default 600) as each turn's inactivity limit: the longest the harness may go without writing to its event stream, measured from the moment the harness process starts or from its last write, whichever is later.
- `[x]` **ALT-EVAL-CLI-007**: The runner SHALL execute the runs of one batch sequentially, one at a time.
- `[x]` **ALT-EVAL-CLI-008**: The runner SHALL print, for each batch, a human-readable summary with one line per run giving the eval ID, run number, status, and the run's priced cost (ALT-EVAL-COST-008), then the batch's total priced cost, then the batch directory's path; in the single-batch form it SHALL print it when the batch ends, however it ends, and in a roster as ALT-EVAL-ROSTER-009 provides.
- `[x]` **ALT-EVAL-CLI-017**: Where the runner has no prices for a batch's model, its summary SHALL show each run's harness figure (`total_cost_usd`) in place of the priced cost, and in place of the total the sum of the harness figures its runs reported, labeled as the harness's and stating how many runs reported none.
- `[x]` **ALT-EVAL-CLI-018**: The runner SHALL exit with status 0 when every batch it ran ended `complete`, 130 when it received an interrupt (ALT-EVAL-RUN-008), and 1 when any batch ended `aborted` for another reason or a roster left a queued batch unstarted; with `--estimate`, it SHALL exit 1 when any model got no projection (ALT-EVAL-COST-013), unless it received an interrupt.
- `[x]` **ALT-EVAL-CLI-014**: When `--roster PRESET` is given, the runner SHALL take its positional arguments as one or more OpenRouter model IDs, in place of the single-batch form's skill, selector, and model.
- `[x]` **ALT-EVAL-CLI-015**: When `--roster` names a preset the runner does not define, the runner SHALL exit non-zero before staging anything, naming the presets it defines.
- `[x]` **ALT-EVAL-CLI-016**: The runner SHALL exit non-zero before staging anything, naming the problem, when `--runs` is given with `--roster`, `--lanes` is given without `--roster`, the same model ID is named twice, `--max-cost` is not above zero, or `--lanes` is below one.
- `[x]` **ALT-EVAL-CLI-009**: The runner SHALL use only the Python standard library.
- `[x]` **ALT-EVAL-CLI-010**: The runner SHALL be executable as `tools/alt-model-evals/run_eval.py` from the repository root, and SHALL take the repository root to be the parent of the parent of the directory containing the runner (`tools/alt-model-evals/../..`), not the current directory.

## Credentials

- `[x]` **ALT-EVAL-KEY-001**: The runner SHALL read the OpenRouter key only from the `OPENROUTER_API_KEY` environment variable.
- `[x]` **ALT-EVAL-KEY-002**: When `OPENROUTER_API_KEY` is unset or empty, the runner SHALL exit non-zero before staging anything, with a message naming `OPENROUTER_API_KEY`.
- `[x]` **ALT-EVAL-KEY-003**: The runner SHALL pass the OpenRouter key to the harness only through process environments, SHALL NOT place the key's value in the argument list of any process it starts (the `docker` command included), and SHALL NOT write the key's value into any file.
- `[x]` **ALT-EVAL-KEY-004**: Before writing a run's outputs to the workspace, the runner SHALL replace every literal, byte-for-byte occurrence of the OpenRouter key with `[REDACTED]` in every captured regular file — `events.jsonl`, `stderr.log`, `response.md`, `changes.patch`, `git-log.txt`, and every regular file under the captured `project/` — leaving symbolic links untouched and each file's permission mode unchanged.

## Staging

- `[x]` **ALT-EVAL-STAGE-001**: For each run, the runner SHALL create a new scratch directory under `$XDG_CACHE_HOME/lid-alt-evals/` (or `~/.cache/lid-alt-evals/` when `XDG_CACHE_HOME` is unset), whose name is random and contains no part of the skill name, eval ID, or eval name.
- `[x]` **ALT-EVAL-STAGE-002**: The runner SHALL write each entry of the eval's `files` list to `project/<path>` inside the scratch directory with the entry's `content` exactly as given, applying no normalization, and creating parent directories as needed.
- `[x]` **ALT-EVAL-STAGE-003**: When any selected eval has a `files` entry whose `path` is absolute, contains a `..` segment, or has `.git` as its first segment, the runner SHALL exit non-zero before running any eval, naming the eval and the path.
- `[x]` **ALT-EVAL-STAGE-004**: The runner SHALL initialize `project/` as a git repository and make one commit of its full contents, with author and committer identity `eval <eval@localhost>` and the commit message `fixture`; for an eval with no files, that commit SHALL be an empty commit with no placeholder file.
- `[x]` **ALT-EVAL-STAGE-005**: At the start of an invocation, the runner SHALL copy into a snapshot, in a scratch directory of the invocation's own, exactly the files under `plugins/` that the tree ID of ALT-EVAL-STAGE-011 covers, preserving their relative layout and keeping symbolic links as links, and SHALL stage each run's `plugins/` from that snapshot, never from the repository.
- `[x]` **ALT-EVAL-STAGE-006**: The `plugins/` snapshot and every run's staged `plugins/` copy SHALL contain no directory named `evals` and no directory whose name ends in `-workspace`, at any depth.
- `[x]` **ALT-EVAL-STAGE-007**: The runner SHALL write the harness configuration to `opencode.json` in the scratch directory, containing exactly five top-level keys and no others: `"autoupdate": false`, `"share": "disabled"`, an `agent` object that disables the `title` agent, a `provider` object whose `openrouter` entry's API key option is the literal string `{env:OPENROUTER_API_KEY}`, and a `skills` object whose `paths` list holds exactly the staged `plugins/` directory as the harness sees it.
- `[x]` **ALT-EVAL-STAGE-008**: The runner SHALL send the model one message built from a fixed template that states, in order: that it is executing one eval run of an agent skill and the current directory is the whole repository; the skill's name, to be loaded with the harness's skill tool, and the directory holding sibling skills; the eval's `prompt`, quoted verbatim, to execute per the skill with any file changes made directly; that the run is non-interactive, so where the skill would ask the user it takes the skill's stated default and states in its final response which defaults it took (for an eval with a `follow_up`, the line in ALT-EVAL-STAGE-013 instead), and today's date; and that its final message must be the exact user-facing response and nothing else.
- `[x]` **ALT-EVAL-STAGE-009**: The run prompt SHALL NOT contain the eval's ID, the eval's name, or any assertion text.
- `[x]` **ALT-EVAL-STAGE-010**: When a run's outputs have been captured, the runner SHALL delete that run's scratch directory, whatever the run's status.
- `[x]` **ALT-EVAL-STAGE-011**: When an invocation starts, immediately before taking the snapshot of ALT-EVAL-STAGE-005, the runner SHALL compute the git tree ID of the repository's whole `plugins/` directory as it exists on disk, its `evals/` directories included (tracked and untracked files, excluding gitignored ones), using a temporary index, without modifying the repository's own index, working tree, or history, and SHALL use that tree ID for every batch the invocation starts.
- `[x]` **ALT-EVAL-STAGE-012**: The runner SHALL keep the harness's session state inside the run's scratch directory, persisting between the run's turns: in container mode by setting `XDG_DATA_HOME` to a `state/` folder mounted read-write at `/work/state`, and without a container in the run's private home.
- `[x]` **ALT-EVAL-STAGE-014**: The runner SHALL delete the `plugins/` snapshot when the invocation ends, however it ends.
- `[x]` **ALT-EVAL-STAGE-015**: At the start of an invocation, when it takes the snapshot of ALT-EVAL-STAGE-005, the runner SHALL read every `evals.json` the invocation's batches use, and SHALL take each batch's prompts, fixtures, assertions, and follow-ups from that reading.
- `[x]` **ALT-EVAL-STAGE-013**: When the eval has a `follow_up`, the runner SHALL replace the template's non-interactive line with one stating that the user will read the final message and reply, and that where the skill directs the model to ask the user it asks in its final message and stops, without answering for the user.

## Harness and sandbox

- `[x]` **ALT-EVAL-BOX-001**: The runner SHALL invoke the harness as `opencode run --pure --auto --format json -m openrouter/<model-id> <prompt>`, passing each element as a separate argument with no shell interpretation, and with stdin closed.
- `[x]` **ALT-EVAL-BOX-002**: The runner SHALL define the harness version as a single constant, and use that constant for the image build, the `--no-container` invocation, and every recorded `harness` value, written `opencode-ai@<version>`.
- `[x]` **ALT-EVAL-BOX-003**: `tools/alt-model-evals/Dockerfile` SHALL build from a Node base image pinned to an exact version tag, and install `git`, `ripgrep`, and `opencode-ai` at the version passed as a build argument.
- `[x]` **ALT-EVAL-BOX-004**: The runner SHALL tag the image with the harness version and a hash of the Dockerfile's contents, and SHALL build the image when no image with that tag exists.
- `[x]` **ALT-EVAL-BOX-005**: Unless `--no-container` is given, the runner SHALL execute each run's harness inside a new container started through the `docker` command.
- `[x]` **ALT-EVAL-BOX-006**: When `--no-container` is not given and `docker info` fails, the runner SHALL exit non-zero before staging anything, stating that no container runtime is reachable and naming `--no-container` as the unsandboxed alternative.
- `[x]` **ALT-EVAL-BOX-007**: The container SHALL mount the run's `project/` read-write at `/work/project` as its working directory, the run's `plugins/` read-only at `/work/plugins`, the run's `opencode.json` read-only at `/work/opencode.json` with `OPENCODE_CONFIG` set to that path, the run's `state/` read-write at `/work/state` with `XDG_DATA_HOME` set to that path, and a generated `passwd` file and `group` file read-only at `/etc/passwd` and `/etc/group`, each holding one entry for the invoking user's UID and GID with home directory `/home/eval`.
- `[x]` **ALT-EVAL-BOX-008**: The container SHALL have no host mounts other than those named in ALT-EVAL-BOX-007.
- `[x]` **ALT-EVAL-BOX-009**: The container SHALL run with a read-only root filesystem, and with `/home/eval` and `/tmp` on in-memory filesystems writable by the invoking user's UID.
- `[x]` **ALT-EVAL-BOX-010**: The container SHALL run as the invoking user's UID and GID.
- `[x]` **ALT-EVAL-BOX-011**: The container SHALL run with all Linux capabilities dropped, with privilege escalation disabled, with a memory limit of 2 GiB, and with a limit of 512 processes.
- `[x]` **ALT-EVAL-BOX-012**: The container's environment SHALL contain only `OPENROUTER_API_KEY`, `HOME=/home/eval`, `OPENCODE_CONFIG`, `XDG_DATA_HOME=/work/state`, `GIT_AUTHOR_NAME` and `GIT_COMMITTER_NAME` set to `eval`, `GIT_AUTHOR_EMAIL` and `GIT_COMMITTER_EMAIL` set to `eval@localhost`, and locale variables, in addition to what the image defines.
- `[x]` **ALT-EVAL-BOX-016**: When `--no-container` is not given and the container runtime reports less total memory (`docker info` `MemTotal`) than the container memory limit of ALT-EVAL-BOX-011 times the number of batches the invocation can run at once (the smaller of `--lanes` and the number of batches queued; one for the single-batch form), the runner SHALL exit non-zero before staging anything, stating both amounts and that the runtime needs more memory.
- `[x]` **ALT-EVAL-BOX-017**: Unless `--no-container` is given, the runner SHALL produce `changes.patch` and `git-log.txt` by running git inside a second container started from the same image, with the settings of ALT-EVAL-BOX-009 through ALT-EVAL-BOX-011, no network, the run's project mounted read-write at `/work/project`, an empty output directory mounted read-write at `/work/out`, the `passwd` and `group` files of ALT-EVAL-BOX-007, and no `OPENROUTER_API_KEY` in its environment.
- `[x]` **ALT-EVAL-BOX-018**: Unless `--no-container` is given, once a run's harness has started the runner SHALL NOT run git on the host in, or on any path inside, that run's project directory, and SHALL NOT read, write, or delete any path inside the project's `.git`.
- `[x]` **ALT-EVAL-BOX-019**: The capture step's git commands SHALL disable `core.fsmonitor`, set `core.hooksPath` to `/dev/null`, and pass `--no-ext-diff` and `--no-textconv` to `git diff`.
- `[x]` **ALT-EVAL-BOX-013**: When `--no-container` is given, the runner SHALL print a warning, before the first run starts, that the model can read any file the invoking user can read.
- `[x]` **ALT-EVAL-BOX-014**: When `--no-container` is given, the runner SHALL run the harness through `npx -y opencode-ai@<version>` in the run's `project/` directory, with `HOME` and every `XDG_*` base directory set inside a throwaway directory created for that run alone, outside the scratch directory, and deleted when the run ends; and with an environment containing only `OPENROUTER_API_KEY`, `PATH`, `HOME`, the `XDG_*` variables, `OPENCODE_CONFIG`, the git identity variables of ALT-EVAL-BOX-012, locale variables, and `npm_config_cache` set to the invoking user's npm cache.
- `[x]` **ALT-EVAL-BOX-015**: When `--no-container` is given, the run prompt SHALL give the skill paths under the scratch directory's `plugins/` instead of `/work/plugins`.

## Run lifecycle

- `[x]` **ALT-EVAL-RUN-001**: The runner SHALL assign each run exactly one status: `completed`, `harness_error`, `timeout`, or `interrupted`.
- `[x]` **ALT-EVAL-RUN-002**: When the harness exits with code zero and its event stream contains no top-level event of type `error` (a line of the stream that parses as a JSON object whose own `type` field is `error`), the runner SHALL record the run as `completed`, including when the final message is empty.
- `[x]` **ALT-EVAL-RUN-003**: When the harness exits non-zero, or its event stream contains a top-level event of type `error` (as defined in ALT-EVAL-RUN-002), the runner SHALL record the run as `harness_error`, with the error's message; a failed tool call inside the stream does not by itself make a run a `harness_error`.
- `[x]` **ALT-EVAL-RUN-004**: When a turn reaches its run limit (ALT-EVAL-CLI-006), the runner SHALL stop it and record it as `timeout` with `timeout_limit` `run`.
- `[x]` **ALT-EVAL-RUN-005**: When the runner stops a run, it SHALL stop the run's container, or under `--no-container` the harness's whole process group, by sending a termination signal and then killing whatever remains after 10 seconds, before capturing outputs; the capture step SHALL remove any leftover `.git/index.lock` in the project before running git.
- `[x]` **ALT-EVAL-RUN-006**: The runner SHALL capture outputs for every run, whatever its status, including partial project state from runs that errored, timed out, or were interrupted.
- `[x]` **ALT-EVAL-RUN-007**: When two runs in a row within a batch end as `harness_error`, counted across eval boundaries, the runner SHALL run nothing further in the batch, recording its state and stop reason as ALT-EVAL-OUT-012 provides.
- `[x]` **ALT-EVAL-RUN-008**: When the runner receives an interrupt (SIGINT, SIGTERM, or SIGHUP), it SHALL stop every run in progress, record each as `interrupted` (a run whose follow-up turn it stopped included), capture its outputs, delete its scratch directory, record each batch it stopped as `aborted` with stop reason `interrupted`, start no further run or batch, and exit non-zero.
- `[x]` **ALT-EVAL-RUN-009**: When an eval has a `follow_up` and the run's first turn completed, the runner SHALL run the follow-up prompt as a second harness invocation that continues the first turn's session, with its own run limit and inactivity limit.
- `[x]` **ALT-EVAL-RUN-010**: When an eval has a `follow_up` and the run's first turn did not complete, the runner SHALL NOT run the follow-up and SHALL record the follow-up's status as `skipped`.
- `[x]` **ALT-EVAL-RUN-011**: The runner SHALL record a run's status as its first turn's status, whatever the follow-up turn's status, except as ALT-EVAL-RUN-008 provides for an interrupt.
- `[x]` **ALT-EVAL-RUN-013**: When the `docker` command that starts a run's harness container exits non-zero, the runner SHALL record the run as `harness_error`, as for any non-zero harness exit (ALT-EVAL-RUN-003).
- `[x]` **ALT-EVAL-RUN-012**: When a turn reaches its inactivity limit (ALT-EVAL-CLI-013) before its run limit, the runner SHALL stop it and record it as `timeout` with `timeout_limit` `inactivity`.

## Rosters

- `[x]` **ALT-EVAL-ROSTER-001**: The runner SHALL define a roster preset named `capability` made of five batches, in this order: `linked-intent-dev` evals 0 and 1 with 10 runs of each eval; `linked-intent-dev` evals 2 and 3 with 10 runs of each; `lid-coach` evals 10 and 11 with 10 runs of each; `lid-coach` evals 15 and 16 with 10 runs of each; and `update-lid` with all evals and 1 run of each. The preset SHALL name its evals as single IDs, never as ranges.
- `[x]` **ALT-EVAL-ROSTER-002**: The `capability` preset's cost probe SHALL be one run of `linked-intent-dev` eval 0 and one run of `lid-coach` eval 15.
- `[x]` **ALT-EVAL-ROSTER-003**: Each batch of a roster SHALL produce the outputs a single-batch invocation of the same skill, eval selector, model, and run count would produce, apart from the roster fields of ALT-EVAL-OUT-022.
- `[x]` **ALT-EVAL-ROSTER-004**: When a roster names several models, the runner SHALL queue its batches interleaved by model: the preset's first batch for each model, in the order the models were named, then the preset's second batch for each model, and so on.
- `[x]` **ALT-EVAL-ROSTER-005**: With `--roster`, the runner SHALL accept `--lanes N` (a positive integer, default 1) and keep N batches running while batches remain queued, starting the next queued batch as soon as a running one ends.
- `[x]` **ALT-EVAL-ROSTER-006**: Before any batch of a roster starts, the runner SHALL check every batch's skill name, eval selector, and fixture paths as ALT-EVAL-CLI-002, ALT-EVAL-CLI-004, and ALT-EVAL-STAGE-003 check a single batch's, and exit non-zero if any check fails.
- `[x]` **ALT-EVAL-ROSTER-007**: When two runs in a row within a batch of a roster end as `harness_error` (ALT-EVAL-RUN-007), whether or not that batch has runs left, the runner SHALL start no further run of that batch's model: each of the model's other started batches with runs left SHALL end `aborted` with stop reason `harness_errors`, its queued batches SHALL NOT start, and its runs already in progress SHALL finish; other models' batches SHALL continue.
- `[x]` **ALT-EVAL-ROSTER-008**: When the runner itself fails in one lane of a roster (an error in its own staging, capture, or output writing, not a run's own status), it SHALL stop the run in progress in every lane, recording each run it stopped, in the failing lane or another, as `interrupted`, record every batch it stopped, the failing one included, as `aborted` with stop reason `runner_error`, start no further batch, and exit non-zero.
- `[x]` **ALT-EVAL-ROSTER-009**: When a roster ends, however it ends, the runner SHALL print each started batch's summary (ALT-EVAL-CLI-008) once, then each model's total priced cost, then each queued batch that never started, naming its model, skill, and evals.
- `[x]` **ALT-EVAL-ROSTER-010**: A batch of a roster SHALL start when its first run is about to start, after the stop checks of ALT-EVAL-ROSTER-007 and ALT-EVAL-COST-017 pass for its model; a batch that never starts SHALL claim no batch directory.
- `[x]` **ALT-EVAL-ROSTER-011**: When a batch of a roster ends, the runner SHALL print one line naming its model, skill, eval IDs, state, and total priced cost.
- `[x]` **ALT-EVAL-ROSTER-012**: In a roster, the runner SHALL apply `--timeout`, `--idle-timeout`, `--effort`, `--variant`, and `--no-container` to every batch, cost probe batches included.

## Cost

- `[x]` **ALT-EVAL-COST-001**: Before staging anything, the runner SHALL read each model's entry from OpenRouter's public model list at `https://openrouter.ai/api/v1/models`, sending no API key, and take from it the model's per-token prices for prompt tokens, completion tokens, internal reasoning, cache reads, and cache writes.
- `[x]` **ALT-EVAL-COST-002**: When the model list holds no entry whose ID equals a requested model's ID, the runner SHALL exit non-zero before staging anything, naming that model.
- `[x]` **ALT-EVAL-COST-003**: When a requested model's entry does not list tool calling among its supported parameters, the runner SHALL exit non-zero before staging anything, naming that model and stating that the harness needs tool calling.
- `[x]` **ALT-EVAL-COST-004**: When the model list cannot be fetched or parsed, or a model's entry lists no prompt or no completion price, the runner SHALL print a warning and run that model without prices; with `--estimate` or `--max-cost` given, it SHALL instead exit non-zero before staging anything.
- `[x]` **ALT-EVAL-COST-005**: The runner SHALL compute a turn's priced cost as its `input` token count times the prompt price, plus its cache-read token count times the cache-read price, its cache-write token count times the cache-write price, its `output` token count times the completion price, and its `reasoning` token count times the internal-reasoning price, using the token counts summed from the turn's event stream.
- `[x]` **ALT-EVAL-COST-006**: The runner SHALL use each price a model's entry lists as listed, zero included. Where a model's entry lists no internal-reasoning price, the runner SHALL price reasoning tokens at the completion price; where it lists no cache-read or no cache-write price, the runner SHALL price those tokens at the prompt price.
- `[x]` **ALT-EVAL-COST-007**: The runner SHALL price every turn that ran, whatever its status, and SHALL price a turn whose event stream reports no token counts at zero.
- `[x]` **ALT-EVAL-COST-008**: A run's priced cost SHALL be the sum of the priced costs of its turns.
- `[x]` **ALT-EVAL-COST-009**: When `--estimate` is given, the runner SHALL run the cost probe in place of the batch or roster and exit without running the batch or roster.
- `[x]` **ALT-EVAL-COST-020**: With `--estimate`, the runner SHALL make every check it makes before running the batch or roster (ALT-EVAL-CLI-002, ALT-EVAL-CLI-004, ALT-EVAL-STAGE-003, ALT-EVAL-ROSTER-006, ALT-EVAL-COST-002, ALT-EVAL-COST-003) before the probe starts.
- `[x]` **ALT-EVAL-COST-010**: The cost probe SHALL be, in the single-batch form, one run of the lowest eval ID the selector selects; and for a roster, the preset's probe runs for each model, run as one probe batch per skill.
- `[x]` **ALT-EVAL-COST-011**: The runner SHALL stage, sandbox, limit, and give follow-up turns to probe runs exactly as it does other runs, and in a roster SHALL run probe batches in its lanes.
- `[x]` **ALT-EVAL-COST-012**: When every planned probe run of a model ran and completed, its follow-up turn included, the runner SHALL print for that model its per-token prices, the probe's total priced cost, the projected cost — the mean priced cost of its probe runs times the number of runs the batch or roster would make for that model — and the projected run time — the mean elapsed time of its probe runs, from staging through capture, times that same number of runs.
- `[x]` **ALT-EVAL-COST-013**: When any planned probe run of a model did not complete, its follow-up turn did not complete, or it never started, the runner SHALL print that model's probe runs' statuses and error messages in place of its projection, reporting a probe run that never started as not started.
- `[x]` **ALT-EVAL-COST-014**: With `--estimate` and `--roster`, the runner SHALL print a projected wall-clock time for the roster, found by assigning each queued batch, in queue order, to the lane that becomes free first, each batch lasting its model's mean probe-run elapsed time times the number of runs the batch makes; models without a projection SHALL be left out of it and named.
- `[x]` **ALT-EVAL-COST-015**: When an interrupt stops a cost probe, the runner SHALL still print the projections of the models whose probe runs had all completed.
- `[x]` **ALT-EVAL-COST-016**: The runner SHALL accept `--max-cost USD` (a number above zero) as a cap on each model's priced spend within the invocation, probe runs included.
- `[x]` **ALT-EVAL-COST-017**: Before starting a run, the runner SHALL sum the priced costs of every finished turn of that run's model in the invocation, whatever their status; when the sum is at or above the cap, the runner SHALL NOT start that run or any later run of that model.
- `[x]` **ALT-EVAL-COST-018**: When the cap stops a model, each of its started batches with runs left SHALL end `aborted` with stop reason `max_cost`, its queued batches SHALL NOT start, and other models' batches SHALL continue.
- `[x]` **ALT-EVAL-COST-019**: When a model reaches the cap, the runner SHALL let that model's runs in progress finish.

## Outputs

- `[x]` **ALT-EVAL-OUT-001**: The runner SHALL write each batch other than a cost probe's (ALT-EVAL-OUT-020) to `<skill-dir>-workspace/alt-model-<YYYY-MM-DD>-<model-slug>/` beside the skill's directory, where the date is the batch's start date and `<model-slug>` is the model ID with every character outside `[A-Za-z0-9._-]` replaced by `_`.

## Recording results

- `[x]` **ALT-EVAL-REC-001**: A `tested_with` entry recording alternate-model results SHALL name the exact OpenRouter model ID and the harness as `opencode-ai@<version>`, taken from the graded runs' `timing.json`.
- `[x]` **ALT-EVAL-REC-002**: A batch SHALL be recorded in `tested_with` only when its `batch.json` `plugins/` tree ID equals the `plugins/` tree of a commit in the repository's history, except as ALT-EVAL-REC-005 provides.
- `[x]` **ALT-EVAL-REC-005**: Where a batch ran on a `plugins/` copy with the capability subsystem removed, ALT-EVAL-REC-002's tree condition SHALL be met instead when the batch's `batch.json` `HEAD` commit is in the repository's history, a case-insensitive search of the copy whose tree ID `batch.json` records, skipping the directories ALT-EVAL-STAGE-006 keeps out of the staged copy, finds `capability` only in passages unrelated to the capability-flag list, and a diff of the whole copy against the `HEAD` commit's `plugins/` shows nothing changed but the subsystem's passages.
- `[x]` **ALT-EVAL-REC-003**: Only `completed` runs SHALL be graded; the pass rate SHALL be computed over completed runs only; and `timeout`, `harness_error`, and `interrupted` runs SHALL appear in neither the pass rate nor the `tested_with` entry.
- `[x]` **ALT-EVAL-REC-004**: A batch with no `completed` runs SHALL NOT be recorded in `tested_with`.
- `[ ]` **ALT-EVAL-REC-006**: A batch whose `batch.json` sets `probe` to `true` SHALL NOT be graded or recorded in `tested_with`.
